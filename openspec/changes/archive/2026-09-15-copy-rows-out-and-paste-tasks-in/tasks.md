## 1. Find out what the board can afford

Two things the design refuses to guess at. Both are read-only and neither
changes any code, so they come first and their answers shape the groups below.

- [x] 1.1 Measure what the store does when many tasks are created at once. A probe under `tests/probes/` that creates tasks in parallel at widths of 5, 10, 20 and 40, using the suites' token and not the board's, naming everything `zz-` and deleting every task it made in a `finally`. Record the widths that succeeded, the error any refusal gave, and the wall time. Passing is a recorded answer to "how many at once is safe", not a green run. **Result: `tests/probes/t_width.py`. 5 of 5 created, 10 of 10, 17 of 20, 5 of 40. The refusals were HTTP 500 naming a server-side queue and its depth -- 3 at a width of 20, 30 at 40 -- so it is the store's queue backing up, not a rate limit, and unpaced a forty-line paste would lose thirty-five tasks silently. Every task the probe created was deleted in its `finally`: 37 of 37. The cap taken forward is 5, below the 10 that passed whole, leaving room for the writes the board makes while a paste runs; design.md records why, and why a refusal is not retried.**
- [x] 1.2 Find out whether the row-mark column has a free cell at its present width of two. Read what each kind of row draws there today — task, mail, event, tracker issue — and confirm a second character fits without the column growing. Record the answer in design.md. If it does not fit, record that the column widens by one and that every view pays a cell for it. **Result: the cell is free. The column is 2 wide and fixed -- `_ROW_OVERHEAD` reserves 1 + 2 + 11 + 11 + padding, so it is not fitted to content. Every kind of row draws exactly one character there: a task its tick box, a mail row `@`, an event `◇`, a tracker issue `▸`. Setting a two-character value left the table's virtual width at 120 and the title column at 85, both unchanged. No widening needed; design.md updated.**

## 2. Reading and writing the text

Pure functions of their input, checked without a board, a store or a terminal.
Everything else in this change depends on them, so they come before the keys.

- [x] 2.1 Write the function that turns a row into a markdown line: empty box for unfinished, ticked box for finished, ticked box with the title wrapped in tildes for cancelled, empty box for a row the board does not own. It takes the title the row carries, not the drawn cell. Verify in a new stub suite `t_copy.py`: one check per state, one for a mail row drawn with a message count beside its subject, one for a title the column would have shortened. **Result: `as_markdown` plus `copy_line` on the board, which picks the title off the row rather than the drawn cell. `t_copy.py` 15/15: a check per state, cancelled proved distinct from finished, a mail row whose drawn cell carries `(4)` copying without it, a title the 60-column board shortened copying whole, and each kind of foreign row copying unfinished with no refusal noticed.**
- [x] 2.2 Write the function that turns a pasted line into a title and a finished flag: strip leading whitespace, then a hyphen, asterisk or plus, or a number with a full stop or a bracket; then a checkbox, reading a tick of either letter case as finished; then a pair of tildes wrapping the whole of what is left. A line with no decoration keeps all of itself. Verify in a new stub suite `t_paste.py`: one check per bullet form, one per checkbox form, indentation with tabs and with spaces, a line beginning with a letter, and a line carrying a trailing tag which must survive untouched in the title. **Result: `from_markdown`. `t_paste.py` covers every bullet form, a number with a stop and with a bracket, both box forms and a capital tick, a box with no bullet, tabs and spaces, a plain line, and a trailing tag surviving. Two checks guard against over-eager stripping: `-5 degrees outside` and `+VAT on the invoice` are titles, not empty bullets, because a bullet is only a bullet when whitespace or the line's end follows it.**
- [x] 2.3 Check the two functions against each other in `t_paste.py`: every state a row can be in, written out and read back, gives the title unchanged — and a cancelled row comes back finished, with no tildes left in the title. Passing is the round trip holding for unfinished, finished and cancelled, with the cancelled case asserting the documented loss rather than equality. **Result: the trip holds for all three states, cancelled asserted as coming back finished with no tildes left. It also caught a defect: a task genuinely titled `~~not really struck~~` lost its tildes, because the reader stripped them from any line. Narrowed to strip only where the box was ticked, which is the only line the board writes them on; the spec was corrected to match and a check now asserts the one loss that remains, a finished task whose own title is wrapped in tildes.**
- [x] 2.4 Check in `t_paste.py` that blank lines and whitespace-only lines yield nothing, so a pasted block with blank lines between its items adds no empty tasks. **Result: empty, whitespace and tab-only lines all answer nothing, and so does decoration with nothing after it -- a bare bullet, a bare number, and a bullet with an empty box. That last group came from a defect the first run found: a lone `- ` read as a task titled `-`, because the bullet pattern demanded a space after it. Fixed to accept the line's end as well.**

- [x] 3.2 Draw a marked row so it can be told from an unmarked one and from the selected one, using the cell decided in 1.2. - [x] 3.3 Allow marking on every row the board draws, mail, calendar and tracker rows included, and confirm none of them is refused as unownable. - [x] 3.4 Keep marks across a repaint and across a view change, and drop the mark on a row the board no longer holds. - [x] 3.5 Report the number of marked rows where the board already reports what a view is not showing, counting marks on rows this view does not draw, and say nothing when none is marked. - [x] 3.6 Make escape clear the marks along with the search. Verify by extending `t_search.py`: with both a search and marks in force, one press clears both. ## 5. Pasting in

- [x] 5.2 Give each task of a paste its own place in the day's order, spaced from the day's last place, rather than reading that place once per task. Verify in `t_pastein.py` that several pasted tasks hold distinct stored orders in the sequence they were pasted, and by running `t_add.py` and `t_move.py` whole, which hold the existing ordering rules this must not disturb. **Result: the day's last place is read once per paste and the tasks spaced from it. - [x] 5.3 Create a finished task as a creation with a completion queued behind it, on the placeholder identifier. Verify in `t_pastein.py` that a paste of a ticked line results in both calls, the second against the identifier the creation returned, and that the row is drawn finished. **Result: a ticked line creates then completes, the completion going to the identity the store handed back (`T-new-*`) rather than the placeholder. - [x] 5.4 Send a paste at whatever width 1.1 found safe. - [x] 5.6 Make a paste one undo group that deletes every task it created, naming how many. - [x] 5.7 Stop the title prompt silently reducing a multi-line paste to its first line.
