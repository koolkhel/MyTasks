## 2. The five plain actions

Each acts on one task today. Each is checked by name rather than by trusting
that the rule covers it: a missed one would go on acting on the selected row
and nothing would fail.

- [x] 2.1 Cancelling acts on a marked set, as one undo group. Verify in `t_bulk.py`: three marked tasks are all cancelled, one press of undo brings all three back, and the row under the cursor — unmarked — is untouched. **Result: all three cancelled, the cursor's row untouched, one undo brings all three back, and the report names the count. Also checked with nothing marked, where it still acts on the selected row alone.**
- [x] 2.2 Dating acts on a marked set, asking once. Verify in `t_bulk.py`: the date prompt opens once, the answer is applied to every marked task, and a set marked across two views is dated in both. Check also that no stored order is sent, which is what keeps the destination day's sequence intact. **Result: the picker opens once and names the set ("2 marked task(s)") rather than a title; both marked tasks move and the cursor's row does not; a set marked across the inbox and a day is moved from whichever view is shown. Two `set_schedule` calls went out carrying no stored order, which is what lets a set land on a day without disturbing the sequence already there.**
- [x] 2.3 Filing into a project acts on a marked set, asking once. Verify in `t_bulk.py`: the picker opens once and every marked task is filed. Where any marked task has no project the board confirms first, because a first filing cannot be undone; answering no files none of them. **Result: the picker opens once naming the set; the confirmation counts the rows with no project rather than the set size; answering no files none and sends nothing. - [x] 3.2 The green mark behaves the same way.
